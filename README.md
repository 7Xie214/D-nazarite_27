# 舵轮底盘上台阶控制

本工程使用 STM32H723ZET6、HAL、FreeRTOS CMSIS-RTOS2 和 Keil ARMCC 5，控制舵轮底盘与上层机构完成四级台阶动作。动作圈数均为**减速前电机转子圈数**，每次指令相对该动作开始时的实际反馈位置。

## 电机与控制分工

| 机构 | 电机及总线 |
| --- | --- |
| 上层升降 | CAN3：M3508 ID5、ID2、ID1 |
| 上层双驱动 | CAN3：M2006 ID4、ID3 |
| 底盘前行走轮 | 左前 M3508：CAN1 ID1；右前 M3508：CAN2 ID4 |
| 底盘舵向 | GM6020：左前 CAN1 ID1、右前 CAN2 ID4、左后 CAN1 ID2、右后 CAN2 ID3 |

`Device` 负责电机反馈与 CAN 报文，`algorithm` 提供轨迹规划与 PID，`APP` 将电机与控制器绑定。`upstairs_task` 负责台阶步骤，`ChassisTask` 负责底盘执行；两者通过请求和完成/错误通知协作。当前底盘任务保持左前、右前、左后三个舵向电机的机械零点，右后 GM6020 发送零电压。

## 运动控制方法

- 上层 3508 使用轨迹规划、位置环与速度环；同步动作共用归一化进度，各轴目标按各自圈数缩放。
- 两台 2006 使用公共轨迹、各自的级联控制和限幅同步纠偏。任一侧实际位置进入容差后结束该段，两侧分别以当前实际位置保持；反馈掉线会触发故障。
- 底盘前轮共用轨迹并结合位置、速度反馈和同步纠偏。任一侧到达末端容差后，本段结束并保持各自当前位置。
- 单轴到位判断使用规划结束、实际位置误差和实际速度；对应阈值见 `APP/Inc/MotorApp.h`。完成标志表示代码的到位条件满足，实际姿态仍取决于编码器、机械安装和参数。

## 台阶动作

上层 3508 数组顺序为 CAN3 **ID5、ID2、ID1**；底盘行程顺序为**左前、右前**。下列数值为当前代码配置，修改动作请以 `Task/Src/My_task.c` 和 `Chassis/Inc/Chassis_Conf.h` 为准。

### 第一级

1. 上层 ID2 转 −7.6812 圈，ID1 转 −34.430979 圈，ID5 保持。
2. 上层 ID5、ID1 分别转 +36.5、−36.5 圈，ID2 保持。
3. 双 2006 走 50.19518086 圈；两侧实际行程达到 60% 时启动 ID5 转 −36.5 圈，一侧先到位时也会补发 ID5。等待双 2006 和 ID5 满足本步条件。
4. 双 2006 相对当前实际位置再走 38.5 圈，完成后进入第二级。

### 第二级

1. 上层 ID5、ID1 分别转 +36.5、−36.5 圈，ID2 保持。
2. 双 2006 走 50.19518086 圈；两侧实际行程达到 75% 时启动 ID5 转 −36.5 圈，一侧先到位时也会补发。双 2006 完成且 ID5 已接受请求后进入下一步。
3. 双 2006 再走 40 圈，ID5 可并行运行。
4. ID2 转 −24 圈并实际到位。
5. ID1 转 +36.5 圈，到位后进入第三级。

### 第三级

1. 底盘左前、右前分别转 +12.2969213、−12.2969213 圈。
2. 上层 ID5、ID1 分别转 +36.5、−36.5 圈，两者到位。
3. 双 2006 走 50.19518086 圈。
4. 上层 ID5、ID1 分别转 −36.5、+36.5 圈，两者到位后进入第四级。

### 第四级

1. 底盘左前、右前分别转 +17.2453059、−17.2453059 圈。
2. 上层 ID5、ID1 分别转 +36.5、−36.5 圈，两者到位。
3. 双 2006 走 50.19518086 圈。
4. 上层 ID5、ID1 分别转 −36.5、+36.5 圈，均到位后底盘前轮分别走 +20.402660、−20.4026606 圈。两侧实际行程均达到 35% 时，启动 ID2 转 +31.6812 圈；底盘规划在 40% 停稳保持，等待 ID2 实际到位后继续原行程。等待底盘本段完成和 ID2 到位。
5. ID1 相对当前位置转 +70.930979 圈，实际到位后第四级结束，继续位置保持。

## 启动与调试

正常 RTOS 模式下，`g_upstairs_start` 初始为 0；在 Keil Watch 中改为 1 后放行一次上台阶流程。改回 0 不会暂停或重置。底盘舵向零点保持在任务运行时持续更新。

观察 `g_upstairs_debug.state`、`step`、`axis`、`pair_2006` 和各级的 timing/status；`g_upstairs_debug.fourth_stair.status == 2` 表示第四级最后的 ID1 动作也已到位。`g_upstairs_debug.fourth_stair.id1_return_error_turns` 可观察该动作相对原始目标的误差。CAN 和电机反馈诊断分别见 `g_can_diagnostics` 与各电机的 `rx_count`、`rx_tick`。

参数集中在 `algorithm/Src/PID_Config.c`、`algorithm/Inc/PID_Config.h` 和 `Chassis/Inc/Chassis_Conf.h`；机械零点通过编码器标定后填写。轨迹参考时间不等同于带负载的实际到位时间。
