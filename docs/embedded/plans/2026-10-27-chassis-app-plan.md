# Chassis application implementation plan

> Execute with embedded-implementation; hardware review precedes quality review.

Goal: connect the approved four-wheel solver to eight independent motor loops
and an RTOS task without changing the solver or the upstairs control behavior.

Approved specification: ../specs/2026-10-27-chassis-app-spec.md.

## Task 1: control application and parameters

Create APP/Inc/ChassisApp.h and APP/Src/ChassisApp.c. Add the four independent
configuration records to algorithm/Inc/PID_Config.h and algorithm/Src/PID_Config.c.
Add the speed limit macro to Chassis/Inc/Chassis_Conf.h. Implement the exact API,
ownership, conversion and fault semantics in the specification. Reuse existing
PID_Init, PID_Update_Continuous, Cascade_Init/Reset/Update, DjiMotor_Update,
DjiMotor_IsOnline, Swerve_Calculate and DjiMotor_SendGroup.

Write native checks before the core implementation and run them against default
zero parameters and a temporary usable configuration. Test actual PID feedback
directions, electrical directions, startup/recovery hold and CAN slot outputs.
Review hardware/math correctness, then review code clarity and C99 correctness.

## Task 2: startup and task integration

Create Task/Inc/ChassisTask.h and Task/Src/ChassisTask.c. Use osDelayUntil for a
1 ms cadence and measured tick difference for dt. Initialize ChassisApp once at
task entry. Reuse the Chassis_Task subsequently generated by the user's CubeMX:
update its .ioc entry and generated attributes to 384 words / High2, and forward
its USER CODE body to ChassisTask. Do not create a second thread or create/delete
a placeholder. Reserved wheel modes exit this task immediately without control.

In Core/Src/main.c include DjiMotor.h and call DjiMotor_Init once after peripheral
initialization and before BSP CAN startup/RTOS. Remove the registration call
from MotorApp_Init; document and test the new startup contract. Register the new
application/task source and header files in MDK-ARM/nazarite_27_upstairs.uvprojx.
Existing APP/Task include paths already cover the new files.

Change Device/Src/DjiMotor.c timestamps and 50 ms age checks to HAL_GetTick and
document rx_tick milliseconds in Device/Inc/DjiMotor.h. CAN is enabled before the
kernel starts, so early feedback must not invoke kernel tick ISR assertions.

Update tests/test_dji_motor.c to explicitly model startup registration before
MotorApp_Init. Test that creating both applications never registers twice.
Document velocity command usage and parameters to fill in Chassis/README.md.

Review hardware startup/task ownership, then code quality. Run affected native
suites and the real Keil ARMCC5 build. Leave existing unrelated changes intact;
do not commit, upload, flash or claim board verification.
