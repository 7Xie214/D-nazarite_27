# 双2006直行组

两台2006通过驱动轮共同推动机构。APP拥有公共轨迹、同步纠偏和组状态，
Device继续负责编码器换算和CAN组帧。假定两轮有效半径和传动比相同；
编码器行程不能检测轮胎打滑或替代机构真实位置传感器。

## 调用和坐标

第三步调用 `MotorApp_Move2006Pair(turns)`，相对本步起点的转子圈数。
正值表示CAN3 ID3负转、ID4正转；负值整组反向。当前首段50.19518086圈，
首段任一2006到位后进入追加行程（用户当前35圈），ID5可同时独立运行。
先检查两台反馈及状态，再一次性记录各自起点。接受后禁止单轴API打断。
保留原3508两步及用户的行程、增益设置。

统一坐标 q3=-(theta3-theta3_start)，q4=theta4-theta4_start。
一条Traj按实际dt生成输出轴参考位置、速度，不因实际位置落后而减慢时钟。
每侧位置环输出与公共速度前馈相加，再按
`v3 -= Ks*(q3-q4)`、`v4 += Ks*(q3-q4)` 加入限幅同步纠偏。
最终速度限制幅值、变化斜率，转换回电机方向后交给独立速度PI。
行进阶段纠偏不产生反方向速度目标；参考结束后允许反向纠偏。
末端总速度沿用各轴位置环限幅，不再额外限制到同步纠偏限幅。
实际电流及机械转动仍受速度环、负载和机构约束。

## Keil Watch

第二步3508等待原因（2026-10-30）：`g_upstairs_debug.step2_axis[0/1/2]`
依次是ID5/ID2/ID1。原切换条件仍是三轴都IDLE，包含保持的ID2；3508仍需
参考结束、位置误差<=0.1转子圈、转子速度<=10rpm，稳定计时当前0。
仅观察抬升到位不足以判断另外两轴是否满足这些条件。

- done_ms：相对进入第二步，各轴首次报告IDLE的时间，0为尚未完成。
- planner_ms / position_ms / speed_ms / settle_ms：按此优先级互斥累计
  的等待原因耗时，起算于运动请求接受，完成后各自冻结。
- last_reason：最后阻塞原因，1规划/2位置/3转速/4稳定计时/5故障。
- last_error_turns / last_speed_rpm / last_command：最后一次阻塞时的
  位置误差、转子rpm和电流指令；不是当前实时值，实时值仍看axis数组。

done_ms最大的轴拖慢第二步。位置等待长说明末端误差没有收敛，转速等待长
说明位置进了容差但速度尚未降到门槛。计时单位ms，HAL采样约1ms分辨率。
这里只增加观察记录，不更改运动参数和3508的完成规则。

分阶段计时（2026-10-30）：展开`g_upstairs_debug.pair_timing[0]`看第三步，
`pair_timing[1]`看第四步，当前段也可看`pair_2006.timing`。单位均为ms：

- accel_ms / cruise_ms / decel_ms：按公共参考速度变化划分的阶段累计时间。
- follow_ms：参考退出后、尚无任何一侧到位的追位时间。
- planner_ms：参考退出相对请求接受的时刻，若实际提前到位也会提前退出。
- first_motion_ms[0/1]：ID3/ID4各自离开起点至少0.01转子圈的首次时刻。
- reach_75_ms：两侧实际进度首次均达到本段75%的时刻。
- first_in_tol_ms[0/1]：ID3/ID4首次进入原始终点容差的时刻；未到位侧仍为0xffffffff。
- stopped_ms[0/1]：对应电机未到位且反馈速度绝对值<=10rpm的累计时间，
  包含起步及中途停顿，会与前述阶段重叠，不代表已确认机械堵转。
- total_ms：请求接受至任一侧到位结束；四个阶段累计时间之和等于total_ms。
- finish_motor_id：先到位并结束本段的电机ID（3或4，0表示未结束）。
- phase：0未开始/1加速/2巡航/3减速/4追位/5到位/6故障。
- status：0未开始/1记录中/2首次到位冻结/3故障冻结。

事件时刻都相对本段接受请求，未发生用UINT32_MAX（0xffffffff）表示。
采用HAL毫秒差值，按控制采样约1ms分段；不是两台实际电机的加减速测量。
任一侧到位结束后，记录不会因保持阶段的位置扰动而重写。下一请求重置当前
记录，任务分别保留两段快照。`timing.step3_after_pair_ms`记录2006组结束至
第四步切换的时间，可能包含补发ID5指令的请求重试，不再等待ID5实际到位。
这些仅用于观察，不改变控制增益、运动参数或步骤切换条件。

`g_upstairs_debug.pair_2006` 包含：

- state：0未启动、1运动、2任一侧到位结束并各自保持、3组故障。
- fault：上述原因编号；actual_turns[0/1]顺序ID3/ID4，均已统一方向。
- reference_turns、sync_error_turns：从本步起点计的转子圈数。
- time_scale：正常运动固定1，掉线故障为0，不再等待落后侧。
- correction_rad_s、speed_command_rpm[0/1]、settled_ms。
- fault_motor_id：掉线触发源ID3或ID4；fault_rx_age_ms[0/1]、
  fault_rx_count[0/1]、fault_command[0/1]保存故障入口的反馈年龄、计数及清零前
  电流指令，数组顺序ID3/ID4。恢复接收后仍保留快照。

旧axis[3]仍为ID4，axis[4]仍为ID3，包含原始方向误差、电流指令/反馈及计数。
旧move_2006_result两项都记录组请求结果；issued=3表示整组接受。
main已切回MOTOR_CURRENT_TEST_ONLY=0，Watch写g_upstairs_start=1释放上楼流程。
