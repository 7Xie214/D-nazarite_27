# 前舵 GM6020 机械零位保持

用户确认由 ChassisApp / ChassisTask 控制，与 upstairs_task 的 CAN3 上层机构分开。
左前 CAN1 ID1、右前 CAN2 ID4 使用现有电机实例及独立 Cascade_t。
任务上电即以约 1kHz 运行，不等待 g_upstairs_start。位置目标为标定机械零角，
使用 Chassis_Conf.h 的 FL/FR ZERO_OFFSET、编码器方向与电压方向；不是首次反馈位置。
位置、速度单位分别为 rad、rad/s，内环输出为 GM6020 原始电压命令。

ChassisApp 新增前舵零位保持入口，仅依赖两台前舵反馈，不要求轮径、底盘几何、
其余六台电机或行走轨迹参数。复用现有绝对编码器换算、转角范围及 PID 状态。
无首帧、超过现有 50ms 离线门槛或越过已配置机械角范围时，该轴输出零并复位；
另一个在线轴继续保持。恢复后重新读取真实机械角，目标仍为零。每拍各发送
CAN1 / CAN2 的 0x1ff 组帧，后舵未启用槽位保持零，不发送 CAN3。

配置增加 CHASSIS_TASK_FRONT_MOVE_ENABLE，默认 0 表示仅前舵零位保持，1 恢复
已有前轮行走/通知流程。仅保持模式下行走请求返回 osErrorResource，避免悬挂请求。
PID 使用 PID_Config.c 的 CHASSIS_PID_CFG[0/1].steer，填入明确标注的 P/P 试调值，
尚未标定的 ZERO_OFFSET 仍由用户填写。其余运动参数和 upstairs_task 不改。

验证：先运行真实 ChassisTask + APP + Device + PID 的仅两路反馈用例，证明原实现
不能输出回零命令；再覆盖跨编码器零、安装方向、无首帧、单边掉线/恢复、扰动纠偏、
限角、两路 CAN 槽位、1ms 调度及原行走模式。O0/O2 本机测试及 Keil 编译链接。
不自动烧录，不将编译或模拟结果视作实机保持能力验证。
